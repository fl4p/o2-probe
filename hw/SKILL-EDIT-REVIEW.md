# Independent review of the kicad-design skill post-mortem edits

codex exec, read-only sandbox, Playwright over CDP to a scratch headless Chrome.
Target: uncommitted SKILL.md / RELEASE.md / GUARDS.md diff, 2026-09-01.

FINDINGS

1. **(c) `RELEASE.md:187–190` — “sourcing class” is an unchecked escape hatch.** `audit_bom.py:110–130` treats every class declared in the same JSON as known and applies semantic checks only to the literal `generic-stock` name. An agent can define `prototype-stock`, `custom`, or another class, add a rationale, and leave a fitted load-bearing part without an orderable or allocated item. Concrete fix: define a closed class schema. Require exact MPNs for load-bearing fitted parts; permit non-MPN classes only for asserted non-procured objects, qualified generic stock with executable minimum specifications and allocated quantity, or custom items bound to a named fabrication/procurement artifact.

2. **(c) `RELEASE.md:183–193` — the prescribed gate does not cross the failure boundary it names.** The defect occurred while a basket was transcribed into purchase orders, but the paragraph only gates schematic-to-BOM classification. `audit_bom.py:257–281` makes the PO snapshot optional and still permits PASS without one; `make_fab.py:472–498` likewise checks it only if the file exists. Concrete fix: whenever parts ordering is claimed, require a released-BOM ↔ basket/PO reconciliation covering every fitted reference, exact MPN/class artifact, and quantity; a missing order snapshot must be `UNVERIFIED` or fail the procurement-release gate.

3. **(a) `GUARDS.md:96–119` — documentation conformance is mislabeled as a second kind of calibration.** The six-step calibration mutates the guard’s subject. A docstring-derived test is instead contract-to-test traceability; it still needs a subject fixture to exercise the claimed branch. The bridge is rhetorical, not the same discipline. Concrete fix: replace the paragraph’s opening with: “Use behavioral prose as a test inventory. For every load-bearing claim, add a named subject fixture that exercises the claimed branch and fails when the claim is false.”

4. **(a) `GUARDS.md:110–119` — the repository and motivating guard do not practise the imposed convention.** Repo-wide grep found no `--selftest` or `def selftest` in `scripts/`. `scripts/vision_probe.py:27–34` makes multiple negative behavioral claims but has neither a test file nor embedded selftest; the same applies to claim-heavy `kicad_repro.py:2–38`, `kicad_netlist.py:2–35`, and `kicad_symlib.py:2–35`. More pointedly, o2-probe’s `audit_mpn_package.py:60–67` asserts the waiver-package comparison, while its selftest at `audit_mpn_package.py:660–721` never executes the waiver branch. Concrete fix: add the exact contradictory-waiver fixture first, then add named tests for the skill’s own claim-bearing guards—or scope the rule explicitly to new/project guards and load-bearing negative claims.

5. **(c) `SKILL.md:364–366` — the land-geometry addition is redundant and creates no new gate.** `SKILL.md:362–363` already orders a pad-size/centre/pin-1 comparison, and `FOOTPRINTS.md:19–29` already says that matching vendor, pin count, body, and package family is only a candidate. There is no contradiction, but the added prose does not require recorded or executable evidence. The still-unfixed L1 pads at `o2-probe.kicad_pcb:7018–7028` demonstrate that naming the distinction can coexist with a known mismatch in prose. Concrete fix: delete `SKILL.md:364–366`, or replace it with a release gate requiring cited recommended-land dimensions and measured emitted-pad dimensions for every selected footprint.

6. **(c) `SKILL.md:358–361` — the actionable rule is followed by unsupported and costly narration.** “Sweep the whole BOM … and record the predicate and its result” is useful; “the single most common way” is an unevidenced empirical superlative that changes no action. `predicate` is also unnecessarily opaque in an always-loaded rule. Concrete fix: retain two lines: “After fixing one instance, run the same BOM filter over every fitted component. Record the filter and complete result beside the finding.”

7. **(c) `SKILL.md:346–366` — none of the edits addresses the protection-clamp root cause.** The old generic min/max and absolute-maximum sentences could catch DZ1 if applied rigorously, but the post-mortem added no rule connecting a protective element’s guaranteed worst-case bound to the limit it protects. Concrete fix: add: “For every clamp or limiter, prove its guaranteed worst-case output at actual current and temperature remains inside the protected device’s limit with the required margin. Typical curves and values specified only at another current do not establish that bound.”
